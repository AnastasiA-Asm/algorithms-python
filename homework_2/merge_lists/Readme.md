    ЗАдача 3. Слияние двух отсортированных связных списков

# Условие задачи

Даны два отсортированных односвязных списка list1 и list2. Нужно объединить их в один отсортированный список, используя узлы исходных списков, и вернуть голову получившегося списка.

Задача решена двумя способами:
- с использоваием фиктивного узла
- без использования фиктивного узла

## Объяснение решения

Оба исходных списка уже отсортированы, поэтому повторно сортировать все элементы не нужно. На каждом шаге сравниваются значения текущих узлов list1 и list2. Узел с меньшим значением присоединяется к результату. После этого указатель соответствующего списка переносится на следующий узел. Переменная tail всегда указывает на последний узел уже объединённой части списка. Если один из списков заканчивается, оставшаяся часть второго списка сразу присоединяется к результату. Результат составляется из узлов двух исходных списков путём изменения их ссылок next.

### Способ без фиктивного узла

В этом способе первый узел результата выбирается отдельно. Сначала проверяются случаи, когда один из списков пустой. Если list1 пуст, возвращается list2. Если list2 пуст, возвращается list1. Если оба списка содержат элементы, сравниваются их первые значения. Узел с меньшим значением становится головой результата head. После этого tail устанавливается на head, а остальные узлы добавляются в основном цикле. Особенность этого способа состоит в том, что первый узел обрабатывается отдельно от остальных.

### Способ с фиктивным узлом

В начале создаётся дополнительный узел dummy. Он временно располагается перед настоящим началом результата. Изначально tail указывает на dummy. Благодаря этому первый настоящий узел присоединяется так же, как и все следующие узлы. После завершения слияния возвращается dummy.next, то есть первый настоящий узел результата. Сам dummy в итоговый список не входит, а его значение не используется при сравнении. Фиктивный узел позволяет не выбирать голову результата отдельно и одинаково обрабатывать все добавляемые узлы.|

## Визуализация слияния

Пример с повторяющимися значениями:

list1 = [1, 4, 4, 9]

list2 = [1, 2, 6, 10]

Ожидаемый результат:

[1, 1, 2, 4, 4, 6, 9, 10]

| Шаг | Сравнение | Выбранный узел | Объединённая часть | Остаток list1 | Остаток list2 |
|---|---|---|---|---|---|
| 0 | Начальное состояние | — | [] | [1, 4, 4, 9] | [1, 2, 6, 10] |
| 1 | 1 ≤ 1 | 1 из list1 | [1] | [4, 4, 9] | [1, 2, 6, 10] |
| 2 | 4 > 1 | 1 из list2 | [1, 1] | [4, 4, 9] | [2, 6, 10] |
| 3 | 4 > 2 | 2 из list2 | [1, 1, 2] | [4, 4, 9] | [6, 10] |
| 4 | 4 ≤ 6 | 4 из list1 | [1, 1, 2, 4] | [4, 9] | [6, 10] |
| 5 | 4 ≤ 6 | 4 из list1 | [1, 1, 2, 4, 4] | [9] | [6, 10] |
| 6 | 9 > 6 | 6 из list2 | [1, 1, 2, 4, 4, 6] | [9] | [10] |
| 7 | 9 ≤ 10 | 9 из list1 | [1, 1, 2, 4, 4, 6, 9] | [] | [10] |
| 8 | list1 закончился | Остаток list2 | [1, 1, 2, 4, 4, 6, 9, 10] | [] | [] |

На каждом шаге tail переносится на выбранный узел.

Когда list1 заканчивается, узел 10 не нужно сравнивать с другими значениями. Оставшаяся часть list2 уже отсортирована, поэтому она целиком присоединяется к результату.


## Пустые списки

Оба способа корректно обрабатывают пустые входные списки.

| list1 | list2 | Результат |
|---|---|---|
| [] | [] | [] |
| [] | [1, 3, 5] | [1, 3, 5] |
| [2, 4, 6] | [] | [2, 4, 6] |

В способе без фиктивного узла эти случаи проверяются до выбора head.

В способе с фиктивным узлом основной цикл просто не запускается, после чего оставшийся список присоединяется к dummy.

## Оценка сложности

Пусть:

- n — количество узлов в list1;
- m — количество узлов в list2.

Каждый узел рассматривается и присоединяется к результату один раз.

Поэтому временная сложность обоих способов равна: O(n + m)

Алгоритмы не создают новые узлы для элементов результата и не используют дополнительные списки.

Дополнительная пространственная сложность равна: O(1) для доп. переменных-сслыок. В способе с фиктивным узлом создаётся один дополнительный узел dummy. Это постоянное количество памяти, поэтому сложность всё равно остаётся O(1).

## Тестирование

Для каждого набора данных отдельно запускаются merge_without_dummy и merge_with_dummy. Обе реализации проверяются на одинаковых наборах данных.
