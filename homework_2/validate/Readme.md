    Задача 2. Проверка последовательностей операций со стеком

# Условие задачи

Даны две последовательности уникальных целых чисел:

- pushed - порядок добавления элементов в стек
- popped - предполагаемый порядок удаления элементов из стека

Последовательность popped является перестановкой pushed: обе последовательности содержат одинаковые элементы, но их порядок может отличаться.

Нужно вернуть True, если последовательность popped можно получить с помощью операций push и pop над изначально пустым стеком. В противном случае нужно вернуть False.

# Объяснение решения

Для проверки используется дополнительный список stack, который имитирует работу стека.

Переменная pop_index хранит индекс элемента из popped, который должен быть удалён следующим.

Алгоритм работает следующим образом:

1. Берём очередной элемент из pushed
2. Добавляем его в stack с помощью append
3. Сравниваем вершину stack со следующим ожидаемым элементом из popped
4. Пока значения совпадают, удаляем вершину с помощью pop и увеличиваем pop_index (цикл while)
5. После обработки всех элементов проверяем, дошёл ли pop_index до конца popped

Если все элементы из popped удалось удалить в требуемом порядке, функция возвращает True. Если часть элементов осталась необработанной, функция возвращает False.

Операция append соответствует push, а операция pop соответствует удалению элемента с вершины стека

В условии цикла сначала проверяется сам список stack. Если stack пустой, он считается значением False. Python прекращает проверку остальных условий после первого False, поэтому программа не обращается к stack[-1] и не вызывает pop для пустого списка. Таким образом, попытка получить элемент из пустого стека не происходит.

## Визуализация допустимой последовательности

Пример:

pushed = [1, 2, 3, 4, 5]

popped = [1, 3, 5, 4, 2]

| Шаг | Выполненные операции | Состояние стека | Следующий ожидаемый элемент |
|---|---|---|---|
| 0 | Начало работы | [] | 1 |
| 1 | push(1), pop(1) | [1] → [] | 3 |
| 2 | push(2) | [2] | 3 |
| 3 | push(3), pop(3) | [2, 3] → [2] | 5 |
| 4 | push(4) | [2, 4] | 5 |
| 5 | push(5), pop(5), pop(4), pop(2) | [2, 4, 5] → [2, 4] → [2] → [] | Все элементы обработаны |

Результат: True.

Последовательность операций:
push(1), pop(1), push(2), push(3), pop(3), push(4), push(5), pop(5), pop(4), pop(2)


## Визуализация недопустимой последовательности

Пример:

pushed = [1, 2, 3, 4, 5]

popped = [4, 3, 5, 1, 2]

| Шаг | Выполненные операции | Состояние стека | Следующий ожидаемый элемент |
|---|---|---|---|
| 0 | Начало работы | [] | 4 |
| 1 | push(1) | [1] | 4 |
| 2 | push(2) | [1, 2] | 4 |
| 3 | push(3) | [1, 2, 3] | 4 |
| 4 | push(4), pop(4), pop(3) | [1, 2, 3, 4] → [1, 2, 3] → [1, 2] | 5 |
| 5 | push(5), pop(5) | [1, 2, 5] → [1, 2] | 1 |

После удаления 5 следующим нужно удалить 1, но на вершине стека находится 2.

Удалить 1 раньше 2 невозможно, потому что стек работает по принципу LIFO: последним добавленный элемент удаляется первым. Новых элементов в pushed больше нет, поэтому продолжить правильную последовательность операций невозможно.

Результат: False.

## Оценка сложности

Пусть n - количество элементов в pushed

Каждый элемент:

- один раз добавляется в стек
- не более одного раза удаляется из стека

Поэтому временная сложность равна O(n)

В худшем случае все элементы одновременно находятся во вспомогательном стеке, поэтому сложность равна O(n)
