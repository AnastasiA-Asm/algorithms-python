# Собственная хеш-таблица

## Условие задачи

Реализовать собственную хеш-таблицу для хранения пар «ключ — значение». Она должна поддерживать добавление, поиск и удаление записей.

Для хранения данных разрешается использовать только списки. Необходимо продумать хранение записей, обработку коллизий и поведение таблицы при заполнении.

## Объяснение решения

Хеш-таблицу можно реализовать методом цепочек или с помощью открытой адресации. При открытой адресации записи хранятся непосредственно в ячейках таблицы. Если нужная ячейка занята, по определённому правилу ищется другая. При этом нужно отдельно учитывать удалённые записи, чтобы не нарушить поиск.

Я выбрала метод скажем так цепочек. Те в этом варианте каждая ячейка содержит список записей. Если несколько ключей попадают в одну ячейку, они сохраняются в общей цепочке. Для поиска нужного ключа достаточно перебрать записи этой цепочки.

Реализация находится в классе HashTable. Общий список buckets содержит внутренние списки — цепочки. Каждая запись тоже представлена списком из двух элементов: ключа и значения. Таким образом, для хранения записей используются только списки.

При создании таблицы задаётся capacity — количество ячеек. По умолчанию их восемь. Переменная size хранит количество записей. Это разные величины: в одной ячейке может находиться несколько записей, а другие ячейки могут оставаться пустыми.

Метод _get_index вычисляет индекс ячейки по формуле hash(key) % capacity. Встроенная функция hash получает хеш ключа, а остаток от деления позволяет получить индекс в пределах таблицы. Разные ключи могут получить одинаковый индекс — это называется коллизией. Поэтому после вычисления индекса мы сравниваем сами ключи в найденной цепочке.

Метод insert сначала проверяет, есть ли ключ в нужной цепочке. Если он уже существует, изменяется только значение. Новая запись при этом не создаётся, поэтому size остаётся прежним. Если ключа нет, пара добавляется в конец цепочки, а size увеличивается на один.

После добавления нового ключа проверяется коэффициент заполнения: size / capacity. Здесь учитывается количество записей, а не количество занятых ячеек. Если результат больше 0.75, вызывается метод _resize. При коэффициенте ровно 0.75 расширение ещё не происходит.

Метод _resize увеличивает количество ячеек вдвое и создаёт новые пустые цепочки. Затем переносит в них все существующие записи. Индекс каждого ключа вычисляется заново, потому что изменился делитель в формуле hash(key) % capacity. Количество записей при переносе не меняется. Расширение может разделить некоторые цепочки, но не гарантирует исчезновение всех коллизий.

Метод get вычисляет индекс ячейки и перебирает её цепочку. Если нужный ключ найден, возвращается его значение. Если ключ отсутствует, возникает ошибка KeyError.

Метод delete ищет ключ таким же способом. Найденная пара удаляется из цепочки с помощью pop, а size уменьшается на один. Остальные записи сохраняются и остаются доступны для поиска. При отсутствии ключа возникает KeyError.

Дополнительно реализован метод __contains__, который позволяет проверять наличие ключа через in и not in. Он возвращает True или False. Проверяется именно ключ, поэтому запись со значением None тоже считается существующей.

Метод __len__ возвращает size и позволяет получить количество записей через len(table).

Начальный размер таблицы должен быть положительным целым числом. Ключи должны поддерживать вычисление хеша, например можно использовать числа и строки. Список использовать как ключ нельзя. Значения могут быть произвольными, в том числе списками или None.

## Оценка сложности

Обозначим:

- n — количество записей;
- c — количество ячеек таблицы.

Оценки ниже предполагают, что вычисление хеша и сравнение ключей занимают O(1).

При достаточно равномерном распределении ключей поиск, удаление и проверка наличия ключа работают в среднем за O(1). Мы вычисляем индекс и просматриваем небольшую цепочку.

Добавление имеет среднюю амортизированную сложность O(1). Это означает, что отдельное добавление может потребовать расширения и переноса записей, но такие расширения происходят редко. Если рассматривать длинную последовательность добавлений, средние затраты на одну операцию остаются постоянными.

В худшем случае все ключи могут попасть в одну цепочку. Тогда поиск, добавление, удаление и проверка наличия ключа требуют O(n), поскольку приходится перебирать записи.

Создание таблицы занимает O(c), так как необходимо создать все пустые цепочки. Расширение занимает O(c + n): создаются новые ячейки и переносятся существующие записи. При расширении из-за заполнения c пропорционально n, поэтому эта операция занимает O(n).

Получение количества записей через len(table) занимает O(1), потому что возвращается уже сохранённое значение size.

Память для хранения таблицы составляет O(c + n): нужны списки ячеек и пары с записями. При последовательном добавлении это обычно O(n). После удаления таблица автоматически не уменьшается, поэтому количество ячеек может оставаться большим даже при небольшом количестве записей. Сами объекты ключей и значений при добавлении не копируются.

## Визуализация работы

Разберём пример из теста test_nontrivial_example.

Создаём таблицу с четырьмя ячейками и выполняем следующие действия:

1. Добавляем ключи 1, 5 и 9.
2. Обновляем значение ключа 5.
3. Добавляем ключ 2, вызывая расширение.
4. Удаляем ключ 1.
5. Проверяем оставшиеся записи.

Для положительных целых чисел из этого примера hash(key) равен самому числу. Поэтому при размере таблицы 4 получаем:

- 1 % 4 = 1;
- 5 % 4 = 1;
- 9 % 4 = 1.

Все три ключа попадают в ячейку с индексом 1. Это коллизия, которую мы обрабатываем методом цепочек.

В таблице ниже показаны только непустые ячейки. Все остальные содержат пустые списки.

| Шаг | Операция | Количество ячеек | Количество записей | Содержимое непустых ячеек |
| --- | --- | --- | --- | --- |
| 0 | Создание таблицы | 4 | 0 | Все ячейки пустые |
| 1 | insert(1, "Anna") | 4 | 1 | 1: [[1, "Anna"]] |
| 2 | insert(5, "Maria") | 4 | 2 | 1: [[1, "Anna"], [5, "Maria"]] |
| 3 | insert(9, "Ivan") | 4 | 3 | 1: [[1, "Anna"], [5, "Maria"], [9, "Ivan"]] |
| 4 | insert(5, "Masha") | 4 | 3 | 1: [[1, "Anna"], [5, "Masha"], [9, "Ivan"]] |
| 5 | insert(2, "Oleg") и расширение | 8 | 4 | 1: [[1, "Anna"], [9, "Ivan"]]; 2: [[2, "Oleg"]]; 5: [[5, "Masha"]] |
| 6 | delete(1) | 8 | 3 | 1: [[9, "Ivan"]]; 2: [[2, "Oleg"]]; 5: [[5, "Masha"]] |

На четвёртом шаге ключ 5 уже существует. Меняется только его значение, а количество записей остаётся равным трём.

При добавлении ключа 2 количество записей становится равным четырём. Коэффициент заполнения равен 4 / 4 = 1, что больше 0.75. Поэтому таблица расширяется до восьми ячеек.

При переносе записей индексы вычисляются заново:

| Ключ | Индекс при размере 4 | Индекс при размере 8 |
| --- | --- | --- |
| 1 | 1 | 1 |
| 5 | 1 | 5 |
| 9 | 1 | 1 |
| 2 | 2 | 2 |

Ключ 5 переходит в отдельную ячейку. Ключи 1 и 9 остаются в одной цепочке, потому что их новые индексы тоже совпадают.

После удаления ключа 1 ключ 9 остаётся доступным. Итоговое содержимое buckets:

[
    [],
    [[9, "Ivan"]],
    [[2, "Oleg"]],
    [],
    [],
    [[5, "Masha"]],
    [],
    []
]


Результаты проверок:

table.get(5)  # "Masha"
table.get(9)  # "Ivan"
table.get(2)  # "Oleg"

1 in table   # False
5 in table   # True
9 in table   # True
2 in table   # True

len(table)   # 3


Поиск и проверка наличия ключа не изменяют содержимое таблицы.
