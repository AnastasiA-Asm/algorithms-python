# Задача 2. Permutations

## Объяснение решения и работы алгоритма

Все перестановки находятся через рекурсивный перебор с возвратом. В текущий список path по одному добавляются элементы исходного массива nums. Какие позиции уже использованы, отмечается в списке used и если позиция занята, повторно взять ее в этом варианте уже нельзя.

Для перебора используется внутренняя функция backtrack. В цикле выбирается доступный элемент, его позиция помечается как занятая, а значение добавляется в path. После этого выполняется рекурсивный вызов, который ищет все продолжения с выбранным началом. Найденные перестановки добавляются в локальный result через extend. Затем последний элемент удаляется из path, а его позиция освобождается в used. Это и есть возврат к предыдущему состоянию перед следующим выбором.

Когда длина path совпадает с длиной nums, перестановка готова. В этом случае возвращается [path.copy()]. Копия нужна, потому что при дальнейших возвратах path будет меняться. Дополнительные квадратные скобки нужны из-за формата результата, функция на каждом уровне возвращает список перестановок, даже если нашла всего одну. У каждого вызова свой result, а used и изменяемый path используются при обходе всех веток.

Повторяющиеся значения в условии отдельно не описаны. В этой реализации возвращаются только разные перестановки. Для этого в каждом вызове создается множество seen. Оно хранит значения, которые уже выбирались именно на этом уровне. Так  для [1, 1, 2] нет смысла дважды начинать одинаковую ветку с единицы. При этом вторую единицу можно поставить на следующую позицию, тк в новом вызове будет свое множество seen. used и seen решают разные задачи: первый следит за позициями, второй убирает одинаквые варианты выбора. Реализация рассчитана на массив целых чисел.

Такой перебор дает все нужные варианты, поскольку на каждом шаге рассматриваются все доступные значения. Одна позиция не используется дважды, а после возврата состояние восстанавливается, поэтому выбор в одной ветке не мешает остальным. Пропуск одинаковых значений на одном уровне убирает только дубликаты, их возможные продолжения совпадают. Исходный массив не меняется. Для пустого массива получается [[]], 1 пустая перестановка.

К backtrack подключен tracer из первой задачи. Поэтому при запуске видны текущая часть перестановки, глубина вызова и результат каждой ветки. Во внешней функции декоратор не нужен, поскольку рекурсивно вызывается именно backtrack.

## Сложность

Пусть n обозначает количество элементов. Оценки ниже даны для худшего случая, когда все числа различны. Размер числа, его сравнение и хеширование считаются постоянными.

Без затрат на трассировку время составляет O(n * n!). Получается n! перестановок, и каждую нужно скопировать в отдельный список длины n. Циклы выбора и объединение списков результатов через extend укладываются в эту же оценку. При наличии повторов веток будет меньше, но оценка худшего случая остается прежней.

С включенным tracer время возрастает до O(n^2 * n!). Дело в том, что он печатает не только текущий path, но и весь результат каждого вызова. Одна готовая перестановка длины n появляется в выводе при возврате с каждого из O(n) уровней. Поэтому для фактически запускаемого кода нельзя игнорировать стоимость печати.

На сам ответ требуется O(n * n!) памяти. Если отделить его от служебных данных, то без tracer дополнительная память имеет верхнюю оценку O(n! + n^2). Промежуточные списки result содержат ссылки на готовые перестановки, они не копируют их содержимое. Их размер в сумме ограничен O(n!). Стек, used и общий path занимают O(n), а множества seen на активных уровнях вместе могут занять O(n^2).

При работе tracer дополнительно создаются строки. Сохраненные отступы и представления path занимают O(n^2), а самая длинная строка результата может иметь размер O(n * n!). Поэтому с трассировкой верхняя оценка дополнительной памяти без учета самого ответа составляет O(n * n! + n^2). Общая память с ответом имеет ту же оценку. Полный вывод внутри алгоритма не накапливается. Если его сохраняет внешний код, как capsys в тестах, память для этого учитывается отдельно и может достигать O(n^2 * n!).

## Пример работы

Возьмем массив [1, 2, 3], гже сначала перебираются варианты с единицей на первом месте, затем с двойкой и тройкой. На каждом из этих шагов нужно вернуться назад и попробовать другой доступный элемент.

Ниже приведены события в том же порядке, в каком их печатает tracer. Во время входа в последнем столбце показан path, а при возврате список перестановок, полученный этим вызовом. Глубина внешнего вызова равна нулю. Для записи значений в таблице используются компактные списки без пробелов после запятых.
