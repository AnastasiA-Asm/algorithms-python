# Задача 1. Tracer

## Объяснение решения

Для этой задачи используется декоратор tracer. Он оборачивает исходную функцию и добавляет печать перед ее вызовом и после получения результата. Благодаря этому можно увидеть, как функция углубляется в рекурсию и в каком порядке возвращаются ответы. Само вычисление остается внутри исходной функции.

Глубина хранится в переменной depth, которая изначально равна 0. При входе в обертку сначала создается отступ, по 4 пробела на каждый уровень. Затем печатаются имя функции и переданные аргументы. Здесь используются `*args` и `**kwargs`, чтобы можно было работать как с позиционными, так и с именованными аргументами. Для вывода значений вызывается repr() поэтому строки видны вместе с кавычками.

Перед выполнением исходной функции глубина увеличивается на 1. Если функция вызывает себя, следующий вызов тоже проходит через обертку и получает больший отступ. После завершения вызова счетчик уменбшается, печатается результат и этот же результат возвращается дальше. Отступ сохраняется отдельно для каждого вызова. Поэтому строка возврата оказывается на том же уровне, что и соответствующая строка входа.

Уменьшение счетчика помещено в finally  на случай ошибки внутри рекурсии, иначе глубина могла бы остаться увеличенной и следующий запуск отображался бы неправильно. Ошибка передается вызывающему коду. Строки возврата для такого вызова не будет, поскольку результат не получен. Еще используется wraps, который сохраняет имя и описание исходной функции.

Отступы организуются, потому что каждому увеличению глубины соответствует 1 уменьшение при выходе. Это работает и при нескольких рекурсивных вызовах внутри функции. Когда первая ветка закончилась, глубина восстанавливается и следующая ветка начинается на нужном уровне. Отдельный список со стеком здесь не нужен, его работу показывает последовательность строк с отступами.

У реализации есть границы применения - она предназначена для обычных синхронных функций, вызывающих сами себя. Общий стек взаимной рекурсии разных функций не поддерживается, поскольку у каждой обертки свой счетчик. Для генераторов и асинхронных функций потребовалась бы другая реализация. Ограничение Python на глубину рекурсии также остается, но это не от решения

## Сложность

Здесь оцениваю затраты самого декоратора, время и память исходного алгоритма учитываются отдельно.

Пусть N обозначает количество вызовов, H обозначает максимальное число одновременно активных вызовов. Через L обозначим длину всего напечатанного текста с учетом отступов, а через S максимальный суммарный размер текстовых представлений аргументов и результата одного вызова.

По времени получается O(N + L). В каждом вызове меняется счетчик, формируются строки и печатается вывод. Длину текста тоже нужно учитывать, ведь вывести длинный список дороже, чем одно число. Эта оценка предполагает, что repr() работает за время, пропорциональное длине получаемого текста, как для простых значений и контейнеров в примерах. У пользовательского метода `__repr__` сложность может отличаться.

Верхняя оценка дополнительной памяти составляет O(H^2 + H * S). Сами кадры обертки занимают O(H), но каждый активный вызов еще хранит свой отступ и текст аргументов. Отступы имеют длины 0, 4, 8 и так далее. Их суммарная длина при углублении дает O(H^2). Для текстовых представлений значений достаточно верхней оценки O(H * S). Память исходного алгоритма и его результата в эту оценку не входит. Декоратор возвращает полученный объект без создания копии.

Весь вывод внутри декоратора не накапливается. Если его сохраняет внешний код, ему понадобится еще O(L) памяти. Так происходит в тестах при перехвате вывода через capsys.

## Пример работы

Для разбора выбран вызов fibonacci(3) здесь есть две ветки, поэтому видно не только углубление, но и переход к следующему вызову после возврата.

```python
@tracer
def fibonacci(n):
    if n <= 1:
        return n
    return fibonacci(n - 1) + fibonacci(n - 2)
```

После вычисления fibonacci(2) функция отдельно вызывает fibonacci(1). В таблице имя сокращено до f. Стек записан от внешнего вызова к самому вложенному и показан после каждого события. Глубина относится к вызову, для которого печатается строка.

| Шаг | Событие | Глубина | Стек после события | Результат события |
|---:|---|---:|---|---|
| 1 | Вход в f(3) | 0 | [f(3)] | Ожидает f(2) |
| 2 | Вход в f(2) | 1 | [f(3), f(2)] | Ожидает f(1) |
| 3 | Вход в f(1) | 2 | [f(3), f(2), f(1)] | Базовый случай |
| 4 | Возврат из f(1) | 2 | [f(3), f(2)] | 1 |
| 5 | Вход в f(0) | 2 | [f(3), f(2), f(0)] | Базовый случай |
| 6 | Возврат из f(0) | 2 | [f(3), f(2)] | 0 |
| 7 | Возврат из f(2) | 1 | [f(3)] | 1 + 0 = 1 |
| 8 | Вход в f(1) | 1 | [f(3), f(1)] | Базовый случай |
| 9 | Возврат из f(1) | 1 | [f(3)] | 1 |
| 10 | Возврат из f(3) | 0 | [] | 1 + 1 = 2 |

Соответствующий вывод:

```text
Вызов fibonacci(3)
    Вызов fibonacci(2)
        Вызов fibonacci(1)
        Возврат fibonacci: 1
        Вызов fibonacci(0)
        Возврат fibonacci: 0
    Возврат fibonacci: 1
    Вызов fibonacci(1)
    Возврат fibonacci: 1
Возврат fibonacci: 2
```

На шагах 3 и 8 вызывается fibonacci(1), но на разных глубинах, поэтому отступы различаются. В тесте проверяются результат 2 и весь приведенный вывод с точными отступами.
